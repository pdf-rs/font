# `src/postscript.rs` — a small PostScript interpreter, used only to read Type 1 prologs

## What it does
Type 1 fonts are PostScript programs; this file tokenises them (`Token::Int/Real/Literal/Name/
String/Procedure` via `parsers.rs`), executes them against a `Vm` (slot-mapped dicts, arrays,
strings, an interned literal table, a stack and a dict stack) and exposes the result through
`RefDict`/`RefArray`/`RefItem`, which `type1.rs` then queries for `FontName`, `FontInfo`,
`FontMatrix`, `FontBBox`, `Private`, `CharStrings` and `Encoding`.

Operators implemented (`:292-323`): `abs add array begin currentdict currentfile cleartomark
closefile count copy cvx definefont for def dict dup end exch executeonly eexec exec eq false get
if ifelse index internaldict known length maxlength mark mul noaccess not pop put readonly
readstring string sub true`. `[`/`]` map to mark/endarray. `bind`, `systemdict`, `userdict`,
`errordict` and `StandardEncoding` are pre-seeded; `eexec` runs the following bytes through
`eexec::Decoder` with the file key.

## Differences from the specifications
* This is a *subset* interpreter and is honest about it (unknown operators are `error!`, not
  ignored), but it is the least robust file in the crate: `pop()` on an empty stack
  (`:473`), `Fi`/`get_array_mut` on locked data (`:514`, `:520`, `:535`), `resolve(...).expect(
  "undefined")` (`:644`), `self.dicts.get_mut(dict_key).unwrap()` (`:679`), `stack.get(...)
  .expect("out of bounds")` (`:862-877`), `get_lit(...).expect("no such key")` (`:489`), and a
  `thread_local` "recursion trap" that `panic!`s (`:44-60`). All are reachable from a malformed
  Type 1 font, which is exactly the input a PDF renderer gets.
* `pop_tuple` (`:466-471`) computes `self.stack.len() - T::N` without checking the length —
  a postscript program that underflows the stack panics with an integer overflow in debug and a
  slice panic in release.
* Notable omissions for real-world Type 1 prologs: `xcheck`, `cvi`, `cvr`, `rcheck`, `wcheck`,
  `readonly` is a no-op (fine), `save`/`restore`, `currentglobal`/`setglobal`, `FDBytesRemaining`,
  `CharString` loops that use the `for`-over-string form. Type 1 prologs generated by common
  tools use a handful of these; when one is missing the whole font fails (`error!`), not just
  the operator.
* `for` (`:697-718`) requires all three operands to be `Item::Int` (no real-valued loop) and
  `require!(limit > initial)` for a positive increment, which is stricter than PostScript
  (a `for` with equal bounds is legal and runs zero times).
* `definefont` (`:678-690`) rejects a non-UTF-8 font name with `expect` and makes the dict
  read-only, which is per spec ("the font dictionary must be posted") but prevents `definefont`
  being called twice on the same dict.
* `readstring` (`:757-772`) is implemented against the *executing input* rather than a file
  object; it requires the top of stack to be `Item::File`, so it only works for the `currentfile
  readstring` idiom — which is the only one that appears in Type 1 fonts.
* Mode flags (`read`/`write`/`execute`) are tracked and enforced, but `noaccess`/`readonly`/
  `executeonly` are only consulted on mutation/execution, not on `get`/`put` of dictionary
  entries.
